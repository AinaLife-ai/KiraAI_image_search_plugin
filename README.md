# 以图搜图（image_search）

> 一句话：给机器人发张图，帮你查「这是谁 / 出自哪部作品 / 谁画的 / 原图在哪」。

| 项目 | 内容 |
|---|---|
| 插件名 | 以图搜图 |
| ID | `image_search` |
| 版本 | 2.3.1 |
| 作者 | znq19 |
| 适用框架 | KiraAI `>=2.6.1`（已在 **v3.1.2** 实测通过） |

---

## 一、这个插件能干什么？

机器人收到图片后，普通做法是「让 AI 自己看图猜」，很容易把角色名、作品名编错。
这个插件改成了**真的去网上搜**：把图片发给多个以图搜图网站，拿回真实网页里写的标题、角色、画师、出处，再交给 AI 综合回答。

支持的搜索引擎：

| 引擎 | 擅长什么 | 要不要 Key | 默认 |
|---|---|---|---|
| **SauceNAO** | 二次元插画：Pixiv 出处、画师、角色、相似度 | 要（免费注册） | 开（没填 Key 会自动停用） |
| **IQDB** | Danbooru / Gelbooru 等图库的精确匹配 | 不要 | 开 |
| **trace.moe** | 动画截图：出自哪部番、第几集 | 不要 | 开（只用于「搜番」） |
| **百度识图** | 中文互联网：表情包、梗图、抖音/微博/B站来源 | 不要 | 开 |
| **Yandex 识图** | 俄语区索引，人物/角色补充 | 不要 | 开 |
| **Gemini 谷歌AI搜索** | 让 Gemini 看图并用谷歌搜索验证 | 要（有免费额度） | 开（没填 Key 自动停用） |
| **千问图搜图** | 阿里云百炼的图搜图工具，效果接近网页端 | 要（按次收费） | 开（没填 Key 自动停用） |
| **Google Lens（SerpApi）** | 通用图片、实物、网页来源 | 要（100次/月免费） | **关** |

> 简单说：**不填任何 Key 也能用**（百度 / Yandex / IQDB / trace.moe 四个免 Key 引擎会工作）；想要更准，就免费注册一个 SauceNAO Key，这是二次元识别的主力。
>
> ⚠️ 注意：**两个斜杠命令（`/搜图`、`/搜番`）默认是关闭的**，需要到 WebUI 里手动打开；AI 自动搜图的工具默认开启，开箱即用。

## 二、两种用法

### 用法 1：发命令，立刻出结果（不花 token）

> 默认关闭，请先在 WebUI → 插件 → 以图搜图 → 「命令直达」里打开「启用搜图命令」/「启用搜番命令」。

在群里/私聊里发：

```
/搜图
```
（图片和命令一起发，或者**回复**一条带图的消息）

也可以直接把命令和图放一条消息里发。机器人会直接把搜索结果发出来，**完全不调用大语言模型 = 0 token、不花钱、不受模型影响**。

其他命令：

| 命令 | 作用 |
|---|---|
| `/搜图`、`/识别图片` | 用全部引擎搜这张图 |
| `/搜番` | 只查动画截图出自哪部番、第几集 |

命令词可以在配置里改，也能加白名单限制谁能用。

### 用法 2：让 AI 自己决定要不要搜（自动）

插件注册了两个工具给 AI：

- `search_image`：用户问「这是谁 / 什么角色 / 哪部番 / 原图 / 画师 / 出处 / 来源」时，AI 会自动调用它。
- `search_anime`：用户问「这截图哪部番第几集」时调用。

你什么都不用做，正常聊天就行。插件还会在系统提示里加一句提醒，让 AI 别只凭「图片描述」瞎猜角色名。

> 工具通道为了快，默认**不跑千问**（千问慢且按次收费）。想让工具通道也跑千问，把「LLM 工具通道也跑千问图搜图」打开即可，但会变慢、会花钱。

## 三、安装（三步）

1. 把整个 `image_search` 文件夹放到 KiraAI 的 `data/plugins/` 目录下：

```
KiraAI/
└── data/
    └── plugins/
        └── image_search/
            ├── main.py
            ├── manifest.json
            ├── schema.json
            ├── requirements.txt
            └── README.md   ← 本文件
```

2. 重启 KiraAI（或到 WebUI → 插件管理里点「重载」）。
   依赖 `httpx`、`Pillow` 会自动装；`Pillow` 是可选的，只影响千问的图片压缩，没装也能跑。

3. 打开 **WebUI → 插件 → 以图搜图**，按下面配一下。

> ⚠️ 改了 `manifest.json` / `schema.json` 需要**重启框架**才生效；只改 `main.py` 可以手动重载。

## 四、第一次配置：最少只要做两件事

### 第 1 件事：填 Key（可选，但强烈建议）

| 想用的功能 | 去哪拿 Key | 填到哪 |
|---|---|---|
| 二次元识别（最推荐） | <https://saucenao.com> 免费注册 → API 页 | 「二次元专用引擎 → SauceNAO API Key」 |
| 谷歌 AI 看图 | <https://aistudio.google.com> 免费创建 | 「Gemini → Gemini API Key」 |
| 千问图搜图 | <https://bailian.console.aliyun.com> 创建 | 「千问 → 百炼 API Key」 |
| Google Lens | <https://serpapi.com> 注册 | 「Google Lens → SerpApi Key」 |

**留空 = 该引擎自动停用**，不会报错，其他引擎照常工作。Key 是敏感字段，WebUI 里不会明文显示。

### 第 2 件事：如果你在国内开了系统代理

把「网络与代理 → 国内引擎直连」保持**开启**（默认就是开的）。千问、百度这些国内服务如果被迫绕道海外代理，会又慢又容易断线，这是千问超时最常见的原因。

需要给海外引擎单独指定代理时，填「海外引擎代理」，例如 `http://127.0.0.1:7890`；留空则读系统环境变量。

## 五、配置项大白话说明

### 基础

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 开 | 总开关 |
| 每个引擎返回条数 | 5 | 越多越准，但越占 token |
| 单引擎超时（秒） | 20 | 单个搜索引擎卡住多久算失败（千问另有自己的时限） |
| 结果缓存天数 | 0 | 同一张图在几天内直接返回上次结果，**0 请求 0 token**；填 7 = 缓存一周 |
| 启用相似度阈值 | 开 | 低于阈值的结果不显示，避免噪声 |
| 相似度阈值（%） | 40 | 低于 40% 的匹配会被丢掉 |

### 千问图搜图（会花钱，看仔细）

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用千问图搜图 | 开 | 没填 Key 时实际不跑 |
| 启用图搜图工具 | 开 | ⚠️ 按次收费约 0.048 元/次 |

| LLM 工具通道也跑千问 | **关** | 开了工具通道会变慢且每次收费；命令通道不受影响 |

## 六、常见问题

**Q：装好后什么都没发生？**
A：确认四件事 —— ① 插件在 WebUI 里是「启用 / ready」；② **「启用搜图命令」已经手动打开**（默认是关的）；③ 发的是 `/搜图`（或你在配置里改过的命令词），并且**带了图或回复了带图消息**；④ 看日志里有没有 `[image_search] ready, engines=[...]`。

**Q：提示"没有配置任何搜索引擎"？**
A：所有引擎都被关了，或者开了的引擎都缺 Key。至少留一个免 Key 引擎（百度/Yandex/IQDB），或填一个 SauceNAO Key。

**Q：搜得很慢，甚至 AI 说工具超时？**
A：最常见是 **IQDB 首次请求特别慢**（服务端反爬，实测可能 30 秒以上）。可以：
- 把「结果缓存天数」改成 7，重复图直接秒回；
- 或把「启用 IQDB」关掉；
- 或让管理员把 `bot_config.agent.tool_call_timeout` 调大。

**Q：Yandex 结果是俄语/英文，看不懂？**
A：插件故意不翻译（省时间省 token），交给 AI 自己翻译理解，回答时会用中文。

**Q：千问一直补发"超时或失败"？**
A：检查「国内引擎直连」是否开着、百炼 Key 是否正确、地域是否选对。千问图搜图本身服务端就要十几秒到一两分钟，属正常波动。

**Q：会不会很费 token？**
A：用 `/搜图` 命令 = **0 token**（不进大模型）。AI 自动调用工具时，只有工具结果会进上下文，插件还会按「每个引擎返回条数」截断。工具描述和提示词是固定文字，能被 KiraAI 的 prompt 缓存复用，几乎不额外花钱。

**Q：开了 Google Lens 但报图床上传失败？**
A：目前图床上传会走海外代理，部分代理会返回 412。可以先把「海外引擎代理」留空试试，或暂时关掉 Google Lens（它默认就是关的）。

## 七、给开发者的补充说明

- 插件遵循 KiraAI 插件规范：`main.py` / `manifest.json` / `schema.json` / `requirements.txt`；配置面板由 `schema.json` 自动生成。
- 用到的框架能力：`@on.im_message(Priority.HIGH)`（命令直达）、`@on.llm_request()`（注入固定工具提示）、`@register.tool`（两个工具）、`ctx.message_processor.send_message_chain`、`ctx.get_plugin_data_dir()`（缓存落盘）。
- **全平台通用**：搜索、工具、命令、普通消息都不依赖特定适配器；只有「合并转发」是 QQ 系（NapCat/OneBot）专有能力，通过能力探测启用，其他平台（Telegram / Discord / Webchat / Bilibili / QQ 官方等）自动走普通消息。普通消息超过 1800 字符会按行分段，兼容 Discord 2000 字限制。
- 所有引擎通过 `asyncio.gather` 并行发起；框架工具超时取消时会取消并回收未完成任务。
- 结果缓存以图片 md5 为键，空结果不写缓存。
- 已在 **KiraAI v3.1.2** 用真实加载器验证：manifest 校验、schema 默认值、import、实例化、工具/钩子注册、`initialize`/`terminate` 全通过；连续 6 轮请求的静态 system prompt 逐字节一致，不破坏 prompt 缓存。
